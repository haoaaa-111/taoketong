## 通用老师评估策略

### 交叉验证规则（优先级递减）

1. 点名历史与标签矛盾 → 以历史为优先（硬证据）
2. 用户备注与标签矛盾 → 以备注为优先（细粒度观测）
3. 无历史无备注 → 以标签为准（用户初始判断）
4. 连续 3 次无点名 → 降低风险预期，可能不是严格型

### 评估维度

- **点名触发条件**: 所有老师都是「人少→点名」。从 rollcall-history 观察该课到课率波动，到课率下降的日子点名风险升高。老师性格影响的是**点名后处理**（扣分/警告/不计较），不是触发条件
- **点名后处理**: 从 notes + caught_history + teacher_attitude 推断：严格型扣分严，理解型口头提醒，随机型走形式
- **对缺勤敏感度**: 小班课走几个人就能察觉（阈值低），大班课需要较大波动。结合 teacher_attitude 交叉验证
- **点名方式一致性**: 比较 rollcall_methods 与 rollcall-history 是否一致——如果历史显示从未点名但标签说「严抓」，以历史为准

### 输出要求

在 refined_profile 中：
1. 明确说明选择了哪个候选类型
2. 说明选择理由（引用具体证据：历史/备注/标签的一致性分析）
3. 如果候选类型与标签不一致，解释为什么不一致
